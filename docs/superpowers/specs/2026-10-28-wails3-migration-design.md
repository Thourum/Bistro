# Wails v3 migration design

- **Date:** 2026-10-28
- **Branch:** `experiment/wails3` (cut from `docs/electron-vs-wails-adr`, so the ADR evidence and spike are present)
- **Evidence:** [ADR 0001](../../adr/0001-electron-vs-wails.md) and [its results](../../adr/0001-results.md). The ADR verdict stays no-go under its pre-registered rule. The owner chose to migrate on an experimental branch anyway, because Electron's memory and the WebSocket are the remaining performance blockers after the React work. The decision is recorded as an ADR amendment (see Done criteria).
- **Pinned:** `github.com/wailsapp/wails/v3 v3.0.0`, the version measured in Gate 4. The Go module path stays `github.com/itterno/bistro`.

## Goal

Replace Electron and the localhost WebSocket in a single change. When it's done, Bistro is one Wails v3 process that embeds the sync engine. The React renderer calls typed Go services through generated bindings and receives typed Wails events. The app auto-updates from GitHub releases on macOS, Windows and Linux.

What the ADR measured on the Wails spike (same renderer, macOS, 60 Hz):
- frame times matched slim Electron on every fixture;
- idle memory 149 MiB against 248;
- 545 MiB against 754 after the largest diff;
- DMG 28 MB against 101.

## Decisions

| Topic | Decision |
|---|---|
| Sequencing | Big bang: shell, embedded engine and transport land together. Electron is deleted. |
| Platforms | macOS (WKWebView), Windows (WebView2), Linux (WebKitGTK). |
| Data continuity | Nice to have, not required. No migration code. Settings start fresh. The DB and keychain token are reused only if their paths and service names resolve the same; otherwise the app resyncs and the user re-authenticates. |
| WebSocket | Deleted entirely, including `cmd/bistro-sync`, the port config and the origin checks. |
| Transport | Typed per-domain Wails services (approach A). Handlers are rewritten as service methods, not wrapped. |
| Validation | Generated Wails types replace zod for engine data. zod remains only for genuinely external input (settings files, URLs). |
| Telemetry | Go side: `sentry-go` and `posthog-go`. `@sentry/browser` handles renderer JS errors. |
| Layout | The classic Wails layout at the repo root. |
| Updater | The Wails built-in `pkg/updater` with its GitHub provider, the built-in window, and digest verification through `SHA256SUMS`. |

## 1. Architecture and layout

**One process.** `main.go` does the following, in order:
1. initialises Sentry;
2. builds the `application.App`;
3. opens the SQLite store and runs migrations;
4. constructs the engine: provider cache, orchestrator, sync loop and action queue (today's `server.App.Run`, minus `wsServer`);
5. registers the services, the menu, the window and the updater;
6. runs.

There is no spawn, no ready handshake, no port and no stdin watch. Lifecycle:
- `SingleInstance` (Wails `SingleInstanceOptions`) replaces the `<db>.lock` flock, and a second launch focuses the existing window.
- `OnShutdown` stops the sync loop and closes the DB.

**Repo layout:**

```
main.go                  Wails entry: options, services, menu, window, updater
go.mod / go.sum          moved from go/ (module path unchanged)
cmd/bistro-benchseed/    kept
internal/                moved from go/internal
  engine/                was internal/server minus WS: app lifecycle, provider, config, llm, expertise, syncloop, repo location
  services/              replaces internal/server/handler: one file per domain
  shell/                 replaces electron/src/main: settings, editor launch, updater, telemetry
  …                      store, git, prsync, provider, etc., unchanged apart from import paths
frontend/                moved from electron/src/renderer, plus its Vite, TS, Biome and Vitest config
  bindings/              generated by `wails3 generate bindings`; committed
build/                   Wails per-OS packaging config (darwin, windows, linux)
Taskfile.yml             dev, generate, build, package
sqlc.yaml                moved from go/
```

- **Deleted:** `electron/`, `go/` (after the move), `internal/ws`, `cmd/bistro-sync`, `internal/server/wsaddr.go`, `ready.go`, the WS port settings and `scripts/smoke-macos.sh`.
- **`.gitignore`:** it currently ignores `build/`; add an exception for the root `build/`.
- **`pnpm-workspace.yaml`:** lists `frontend/` and `website/`.
- **Kept, not WS:** the OAuth loopback callback listener used by the auth flow. It's a redirect target, not an API.
- **Untouched:** `website/` and `docs/adr/data/`. The ADR harness keeps its Electron paths as a historical record.

## 2. Services, events and the renderer data layer

### Go services

`internal/services/<domain>.go` holds one struct per domain, with its dependencies as fields; the fields come from today's `handler.*Deps`. The domains follow the 24 handler files:
- `Auth`, `PR`, `Diff`, `Interdiff`, `Patchsets`, `Comments`, `Threads`, `Drafts`;
- `ReadState`, `Viewed`, `Dismiss`, `Triage`, `ReviewQueue`, `Sync`;
- `RepoLocation`, `DevFolderScan`, `Expertise`, `Classification`, `Editor`;
- plus `Shell` (§3).

Each of the 48 message types becomes a typed method:

```go
func (s *Diff) Get(ctx context.Context, req DiffRequest) (DiffResponse, error)
```

- **No raw messages:** every `json.Unmarshal(msg.Data, …)`, `InboundMessage`, `Dispatcher` and `wsServer.RegisterHandler` call disappears. Methods return concrete structs, never `any`, so the generator emits real TS models.
- **Errors:** methods return `*ServiceError{Code, Message}`. `Code` is a small closed set, such as `not_found`, `unauthenticated`, `rate_limited`, `invalid`, `cancelled`, `timeout` and `internal`. The renderer maps codes onto tagged `Fault`s and never parses messages.
- **Recovery:** every exported method runs through a `recover` wrapper. A panic becomes `ServiceError{Code: "internal"}` plus a Sentry event, so the app stays up.
- **Cancellation:** long operations (`Auth.Start`, `DevFolderScan.Scan`) watch `ctx`. Generated calls return a `CancellablePromise`, and `.cancel()` cancels `ctx`. This replaces the `AUTH_CANCEL` and `SCAN_CANCEL` messages and the `onSent` request-ID plumbing.

### Events

**Only true pushes become events.** The rule:
- A key becomes a return value if the engine sends it only in answer to one request.
- A key stays an event if the engine also emits it unprompted, or emits it to report progress during a call.

Today's handler table mixes the two:
- **Responses delivered as broadcasts become return values.** These are the keys routed to `resolveWsResponse`, including `DIFF_READY`, `DRAFTS_READY`, `TRIAGE_READY` and `ACTION_RESULT`, and response-style keys such as `AUTH_CHECK_RESULT`, `REPO_LIST_READY` and `SCAN_DEV_FOLDER_RESULT`.
- **What remains are pushes:** `SYNC_COMPLETE`, `SYNC_ERROR`, `PR_LIST_CHANGED`, `ACTION_COMPLETE`/`ACTION_FAILED`, `DRAFTS_CHANGED`, `CI_STATUS_CHANGED`, `RATE_LIMITED`, `AUTH_TOKEN_EXPIRED`, expertise progress, and so on.

Mechanics:
- **Declaring:** each push is declared once with `application.RegisterEvent[Payload]("sync:complete")`, and the generator emits its TS type.
- **Emitting:** the engine depends on one interface, `Emitter{ Emit(name string, data any) }`, which replaces every `Broadcast` field. Production uses `app.Event.Emit`; tests use a recording fake.

### Renderer

- **Calls:** `frontend/src/services/*.ts` and the hooks call the generated bindings. One helper, `services/engine/call.ts`, wraps each call:
  - `ResultAsync.fromPromise(binding(args), toServiceFault)`, which keeps the `@thourum/fault` chains;
  - an optional timeout: 30 s by default, none for `Auth.Start` and the dev-folder scan. On timeout it calls `promise.cancel()` and returns a `timeout` fault.
- **Events:** the exhaustive handler table in `services/events/index.ts` stays, keyed by the generated event names. It subscribes through `Events.On` from `@wailsio/runtime`.
- **The 29 `window.electron` uses** become calls on the `Shell` service (§3).
- **Deleted:**
  - `services/ws/connection.ts`, `hooks/useWebSocketConnection.ts`;
  - `types/wsSchemas.ts`, the zod response schemas in `types/index.ts`, `parseResponse`;
  - request IDs, `onSent`, and the `connecting`/`disconnected` connection states (`syncStatus` keeps only its sync meanings);
  - `window.d.ts`'s `electron` typing.

## 3. Shell features, updater, telemetry and failure handling

### `internal/shell/`, replacing `electron/src/main`

- **Settings** (`settings.go`):
  - a JSON file at `os.UserConfigDir()/Bistro/settings.json`, with defaults and schema validation in Go;
  - exposed as `Shell.GetSettings`, `SetSettings`, `ResetSettings` and `OpenSettingsFile`;
  - a `settings:changed` event replaces the `settings:*` IPC.
- **Editor launch** (`editor.go`): a port of `editorTarget`, `editorLaunch` and `editorRequest`. It resolves the editor command and runs it with `exec.Command` and no shell. The existing TS cases become Go table tests.
- **Dialogs and links:** `Shell.PickFolder` uses Wails Dialogs, and `Shell.OpenExternal` uses `Browser.OpenURL` (http/https only). `Shell.Quit` calls `app.Quit()`.
- **Window and menu** (`main.go`):
  - one window that restores its size and position from settings;
  - App and Edit menu roles, so copy, paste and undo work in textareas.
- **Bench flags:** `--quit-after-ready` and `--bench-query` are dropped. The renderer's `bench/` module stays, loaded by URL query in dev.

### Updater (`internal/shell/updater.go`)

- **Init:** `app.Updater.Init(updater.Config{...})` with:
  - `CurrentVersion` from `-ldflags` (the tag without its `v`);
  - the provider `github.New(github.Config{Repository: "Thourum/Bistro", Prerelease: true, ChecksumAsset: "SHA256SUMS"})`;
  - `CheckInterval: 6 * time.Hour`.
- **Checks:** one `CheckAndInstall` at launch. The built-in window (release notes, Install / Restart & Apply, Skip This Version, Remind Me Later) is themed through its CSS variables to match `docs/DESIGN.md` tokens.
- **Assets per release:** `bistro-darwin-arm64.zip` (the `.app`), `bistro-windows-amd64.zip`, `bistro-linux-amd64.tar.gz` and `SHA256SUMS`.
  - First-install artifacts (a DMG, an NSIS installer) are named `*-installer.*`, so `DefaultAssetMatcher` ignores them.
  - The updater cannot install `.dmg`, `.msi` or `.pkg`.
- **Trust:** GitHub TLS plus the SHA-256 digest. On macOS, Developer ID signing and notarization run when the `MACOS_*`/`APPLE_*` secrets exist, as today.
- **Disabled:** in dev and untagged builds.

> ponytail: digest-only. If the release pipeline is ever separated from where the signing key lives, move to the `endpoint` provider with a manifest signed by `wails3 updater manifest -key`.

### Telemetry

- **`sentry-go`** is initialised first. Its release is the app version. The Wails `PanicHandler` and the service `recover` wrapper both report to it.
- **`posthog-go`** sends the same events, with the same opt-out setting, as today's `telemetry.ts`.
- **`@sentry/browser`** in the renderer uses the same DSN and release.

### Failure handling

| Failure | Behaviour |
|---|---|
| Panic in a service call | Recovered, reported to Sentry, and the promise rejects with `internal`. The renderer shows its fault toast. Drafts are safe, because the engine owns them in SQLite. |
| Panic in a background goroutine (sync loop, workers) | Each loop has its own `recover`: log, report, then restart with backoff. |
| Deadlocked service call | Only that promise stalls, because Wails runs each call in its own goroutine. The call helper times out, cancels and shows a fault; the rest of the UI keeps working. |
| Fatal runtime error or cgo crash | Takes the whole app down. Accepted: process isolation of the engine is the trade for one process. |

## 4. Build, CI and testing

**`Taskfile.yml` tasks:**
- `dev`: Wails dev with Vite HMR;
- `generate`: `wails3 generate bindings`, then `sqlc generate`;
- `build`;
- `package:darwin`, `package:windows` and `package:linux`, which produce the updater assets and installers from §3.

**CI (`ci.yml`):**
- **Go job** (root): `go vet ./...` and `go test -race ./...`.
- **Frontend job:** type-check, Biome lint and Vitest.
- **Drift check:** `task generate`, then `git diff --exit-code frontend/bindings internal/store/db`.

**Release (`release.yml`):**
- **Gates:** the same security gates (`govulncheck`, `pnpm audit`, gitleaks).
- **Build matrix:** native macOS arm64, Windows amd64 and Ubuntu amd64 runners. CGO SQLite rules out cross-compiling.
- **Per-platform job:** packages, smoke-tests, and uploads its assets plus a line for `SHA256SUMS`.
- **Final job:** assembles the draft pre-release.

**Smoke test** (`scripts/smoke.sh`): launches the packaged app with `--smoke`. The app exits 0 once migrations have run and the window has finished its first navigation, and exits non-zero on error or after a 60 s timeout. Linux runs it under `xvfb-run`.

**Tests.** Write a test only where it would fail if the logic broke.

- **Go:**
  - The handler tests move with their logic to `internal/services/*_test.go`. They call typed methods and assert on the recording `Emitter`.
  - The WS server, dispatch and origin tests are deleted with their code.
  - New tests only for new behaviour: the `recover` wrapper, settings load/validate/defaults, `ctx` cancellation for auth and scan, and the editor launch table.
- **Frontend:**
  - The service and hook tests swap their `wsClient` mocks for `vi.mock` of the generated binding modules.
  - One new test covers `call.ts`: rejection becomes a tagged fault, and a timeout cancels.
  - `wsSchemas.test.ts` is deleted.
- **Manual, macOS:**
  - sign in, sync, and open the kubernetes and google-cloud-go fixture PRs;
  - review with each navigation style (vim, emacs, standard);
  - write drafts and submit;
  - quit and relaunch with the drafts intact;
  - update from one tagged pre-release to the next.
- **Manual, Windows and Linux:** sign in, sync, open a diff, submit a comment.

## Known risks, carried from ADR 0001

These aren't blockers for an experimental branch; they're listed so nobody is surprised by them.

- **Keyboard (macOS):** WKWebView swallows Ctrl+Tab, which is next/previous file in the standard keymap. If the manual pass confirms it, rebind it in `KEYMAPS.standard`. Option dead keys and the Fn/Globe IME issue (Wails #6033) are untested (S6 was skipped).
- **Upstream health:** Wails' median first maintainer response is ≥ 18.9 days (S7). Pin `v3.0.0`, and upgrade deliberately.
- **Platform coverage:** WebKitGTK performance on Linux and WebView2 on Windows were not measured. macOS 13 was not measured either.
- **Transport performance:** the source trace found no guaranteed binding speed-up. Each push event is one `evaluateJavaScript`, with no batching. If a sync burst stutters, batch the pushes into a single event on the Go side.

## Done criteria

1. CI is green, including the drift check, and the release workflow produces all three platforms' assets plus `SHA256SUMS`.
2. The manual macOS pass is clean; the Windows and Linux passes are clean.
3. An installed pre-release auto-updates to the next pre-release through the built-in window.
4. On the packaged macOS app, idle `footprint` summed over the process tree is ≤ 173 MiB, and the first-install DMG is ≤ 40.5 MB. These are the ADR's S3 and S5 limits, re-checked on the real app instead of the spike.
5. `CLAUDE.md`, `AGENTS.md`, `README.md`, `DEVELOPMENT.md`, `docs/go-project-overview.md` and `docs/ALPHA.md` describe the new layout, commands and conventions. That includes replacing the "zod at the edge" and WS transport rules with the generated-bindings rules.
6. ADR 0001 has a dated amendment recording the owner's decision to migrate on `experiment/wails3`, despite the no-go verdict.
