## Foundation hardening (roadmap Phase 0)

- **`16821f5` dynamic WebSocket port + ready signal** — `-ws-port 0` binds a
  random port; after migrations complete and the listener is up, Go prints
  `{"event":"ready","wsPort":N}` to stdout. Fixes port collisions AND the
  initial-launch migration race in one handshake.
- **`fa6db74` Electron adopts the handshake** — spawns Go with `-ws-port 0`,
  parses the ready line, delivers the port to the renderer synchronously via
  preload `additionalArguments`. Crash auto-restarts reuse the last known port.
- **`e64df23` structured logging** — `internal/logging` context helpers
  (`WithLogger`/`FromContext`), a redacting HTTP transport on the GitHub
  client, per-request WS dispatcher loggers, contextual sync/replay logging.
  Secrets never reach log output.

## Sync engine reliability (the big debugging arc)

Symptom: sync silently hung at `phase write-db start`; UI only showed request
timeouts. Three root causes were found and fixed, with defense in depth:

- **`85c6c4e`** — single-instance `flock` on `<db>.lock` (duplicate engine
  exits in <1s with a clear message), `busy_timeout=5000`, 30s GitHub HTTP
  timeout, 2-minute per-PR fetch ceiling, `SYNC_ERROR` broadcast to the UI,
  per-repo + total pass duration logging.
- **`5bbc4be`** — the *actual* deadlock: `syncWatchedRepos` held its `repos`
  result set open across the whole sync while the pool was pinned to ONE
  connection — the write tx waited forever for the connection its own caller
  held. Fixed by draining the query first; pragmas moved into the DSN and the
  pool raised to 4 connections; **stdin watchdog** (`-exit-on-stdin-close`) so
  a killed Electron tree can never leave an orphaned engine holding the DB.
- **`de5f791`** — dev builds spawn Go at debug level (per-PR fetch steps and
  HTTP calls visible); renderer timeouts report socket state and point at
  `bistro-sync.log`.
