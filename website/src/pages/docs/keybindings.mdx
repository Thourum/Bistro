# Keybindings

Bistro is designed for keyboard-first GitHub pull request review. The defaults
below come from `electron/src/renderer/utils/keymaps.ts`; the action catalog lives
in `utils/keybindings.ts`. The in-app help overlay and footer legend show your
effective bindings, including overrides.

## Navigation styles

- **Vim** (default): `j` / `k` movement and short sequences such as `g g`.
- **Emacs**: `Ctrl+n` / `Ctrl+p` movement, `Alt` shortcuts, and `Ctrl+c` prefix sequences.
- **Standard**: arrow keys, Home / End, PageUp / PageDown, and familiar modifier shortcuts.

Choose a style during onboarding or at the top of **Settings → Keyboard**. You
can also set it directly in `settings.json`:

```json
{
  "navigation": { "style": "emacs" }
}
```

`keybindings` overrides apply on top of the chosen style. Switching styles keeps
your overrides; an empty override array disables that action.

In the tables, `Mod` means `Cmd` on macOS and `Ctrl` on Windows/Linux. `Alt` means
Option on macOS. Space-separated keys are a sequence, not a simultaneous chord:
`Ctrl+c Ctrl+a` means press `Ctrl+c`, then `Ctrl+a`. The gap between
sequence steps is up to 500 ms for Vim/Standard and 1,500 ms for Emacs.

:::caution
On Windows/Linux, Emacs's `Ctrl+c` prefix and `Ctrl+x u` undo sequence use the
usual copy/cut shortcuts outside text inputs. In a focused text input, copy and
cut keep their normal behavior; on macOS they remain `Cmd+c` / `Cmd+x`.
:::

:::tip
Open help with `?` (Vim), `Ctrl+h` (Emacs), or `F1` (Standard) in the inbox,
PR detail, or diff to see your current bindings, including overrides.
:::

## Onboarding

| Action | Vim | Emacs | Standard |
| --- | --- | --- | --- |
| Continue to development folder / finish onboarding (`onboarding.continue`) | `Space` | `Space` | `Space` |
| Next navigation style (style step only) | `Tab` | `Tab` | `Tab` |
| Previous navigation style (style step only) | `Shift+Tab` | `Shift+Tab` | `Shift+Tab` |

The first step includes a practice sandbox using your chosen style and overrides.
Its checklist is optional; click **Continue** when ready. In the sandbox inbox,
`Space` also continues unless a button has focus; inside an opened practice PR,
it follows the sandbox's bindings instead (for example, Vim's `Space` opens the
diff). The second step configures your development folder, where `Space` finishes
onboarding unless a button has focus.

## Remapping keys

Open settings with `Cmd+,` / `Ctrl+,` or run `settings` in the command palette
(`:`, `Alt+x`, or `Mod+k`, depending on your style). **Settings → Keyboard** shows
the style picker above your shortcuts. Keybinding overrides are stored locally
in `settings.json` as action ids mapped to key arrays:

```json
{
  "navigation": { "style": "emacs" },
  "keybindings": {
    "list.down": ["x"],
    "list.top": ["g", "g"],
    "list.star": []
  }
}
```

:::info
An empty array disables a binding. Default keys live in
`electron/src/renderer/utils/keymaps.ts`; action ids live in
`utils/keybindings.ts`, and activation rules live in
`electron/src/renderer/utils/keybindingActivation.ts`.
:::
